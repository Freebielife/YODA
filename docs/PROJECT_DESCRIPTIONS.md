# Описание проекта в каждом репозитории

README каждой новой обсерватории содержит краткое описание проекта/токена,
первичные источники и дату их проверки. Сначала сверяется точный контракт;
совпадения названия недостаточно. Предпочтение — официальному сайту,
документации, связанному официальному каналу и метаданным этого контракта.

Текст объясняет назначение проекта и роль токена, когда это подтверждается
источниками. Самоописание из метаданных подписывается как заявление проекта.
Планы и рекламные обещания нельзя выдавать за работающие возможности;
доходность, безопасность и партнёрства требуют отдельного подтверждения.

В project.json используется поле project_description:

```json
{
  "text": "Краткое описание по проверенным источникам.",
  "origin": "reviewed_sources",
  "sources": ["https://OFFICIAL_PROJECT_WEBSITE/"],
  "checked_at": "YYYY-MM-DD"
}
```

Это схема, а не готовые данные. В поле checked_at нужна реальная дата ISO.
Допустимые origin: reviewed_sources (текст составлен после изучения источников)
и token_metadata (самоописание без независимой проверки заявлений).

discover_project автоматически сохраняет содержательное description из метаданных
и вставляет его в README с атрибуцией. Пустое поле, технический hex-адрес или
голая ссылка не считаются описанием. Для текста по официальным источникам
передайте объект выше отдельным JSON-файлом через --description-file или
заполните project_description до запуска scaffold_observatory.

Генератор проверяет структуру, дату и HTTPS-ссылки, а не достоверность утверждений.
Чтение источников и сверка смысла остаются обязательными. При отсутствии сведений
README явно сообщает, что описание ещё не подтверждено; это нужно разрешить до
публикации либо явно согласовать ограничение. Содержание сайта и рыночные данные
не меняются при добавлении описания в README.
