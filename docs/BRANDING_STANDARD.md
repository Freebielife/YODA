# Логотип, флаг и канал проекта — обязательное правило

Применяется к каждой новой TON-обсерватории из TON-Observatory-Template. Существующие сайты автоматически не меняются.

1. **Первый, главный блок:** логотип токена берётся из метаданных именно этого
   контракта. Допустимый второй источник — сайт проекта. Сохраняются URL и тип
   источника; изображение скачивается и встраивается в HTML. Флаг из каталога
   не подставляется вместо логотипа. Если источник недоступен, нужно получить
   рабочий источник логотипа, а не выдавать буквенную заглушку за готовый сайт.
2. **Флаг в остальных разделах:** для каждого токена уточняется конкретный
   флаг/номер в согласованном каталоге TONecoFlags. Подтверждённое соответствие
   задаётся явно. Если флага нет в каталоге либо его файл ещё не подготовлен,
   пользователь предоставляет нужный эмодзи/файл. Случайный похожий флаг,
   флаг другого токена и универсальный №196 без согласования не используются.
   Флаг хранится независимо от логотипа первого блока и применяется к
   обозначениям токена в пулах, ссылках и фоновым эмблемам операций. Несколько
   фоновых эмблем на карточках сохраняются. Размеры ограничены элементами.
3. **Канал проекта:** для ознакомления с проектом обязательна ссылка на его
   Telegram-канал. Она размещается кнопкой «Канал проекта» в первом блоке и в
   «Полезных ссылках»; EN — «Project channel». Нужна ссылка именно этого проекта.
   При отсутствии подтверждённой ссылки она запрашивается у пользователя.
   Произвольные адреса не составляются из названия токена.

Исходный каталог соответствий — mapping.csv из согласованного пользовательского
набора TONecoFlags. В репозитории встроена лишь часть подготовленных графических
ресурсов. Отсутствие изображения во встроенном атласе не означает, что флага нет
в полном каталоге: сначала проверить каталог, затем использовать нужный файл.

## Настройки

Для ручной конфигурации обязательны `logo_file` (локальный WebP),
`logo_origin` (`token_metadata` или `project_website`), `logo_source` (HTTPS),
`links.telegram` и ровно одно из `flag_catalog_key`, `flag_file`, `flag_emoji`.
`flag_file` — локальный WebP/GIF; custom Telegram emoji предварительно
подготавливается из предоставленного файла. `flag_emoji` — явно выбранный
Unicode-эмодзи, который может выглядеть по-разному на разных системах.

Пример полей (условные адреса используются только для документации):

```json
{
  "logo_file": "token-logo.webp",
  "logo_origin": "token_metadata",
  "logo_source": "https://example.org/token-logo.webp",
  "flag_file": "approved-token-emoji.webp",
  "links": {"telegram": "https://t.me/PROJECT_CHANNEL"}
}
```

Автоматическая подготовка использует `--channel`, `--website` и один из
`--flag-key`, `--flag-file`, `--flag-emoji`. Приоритет логотипа — metadata image,
затем `itemprop=logo`, favicon или apple-touch-icon на указанном сайте. Веб-баннер
`og:image` не принимается автоматически за логотип. При нескольких разных
Telegram-ссылках на сайте канал уточняется явно. Формат ссылки проверяется;
проверка URL сама по себе не доказывает, что адрес ведёт именно на канал.

В итоговом project.json поле `branding` сохраняет источник логотипа, выбранного
флага и канал. При сборке нет обращения к внешнему графическому хостингу.
